## 证据引用契约

当前 task patch 始终由运行时自动绑定为每个候选的基础证据。patch 没有可供你填写的编号；不要输出或猜测内部 patch 编号。

如果你在判断候选时使用了 `<evidence_catalog>` 或 `<symbol_context>` 中带编号的外部事实，或工具结果末尾的 `[证据编号 Txx]`，请在 `evidence_refs` 中引用对应的 Cxx/Txx 编号。你只负责选择编号，不得重新填写工具参数、代码片段或工具原文。LLM-facing 编号空间只包含 Cxx/Txx。

每条引用包含:
- alias: 必须逐字复制当前 Evidence Catalog 中存在的编号;
- role: location / mechanism / reachability / impact / counter。

规则:
- 每个候选只选择最小充分证据集，最多选择 3 条与候选直接相关的外部事实;
- 对每条引用执行删除测试：删除该引用后，候选的 mechanism / reachability / impact / counter 主张不会明显变弱，就不得引用;
- 多个工具共同证明不同的必要事实时,同时引用各自编号；证明同一事实时只保留更直接的一条;
- 探索性、重复性、与最终主张无关或被后续事实推翻的调用不要引用;
- 如果本次判断已经使用了会限制或反驳候选的事实，必须以 `counter` 角色引用；不得只引用支持主张的事实而选择性省略直接反证;
- task patch 已经证明的局部机制，不要再引用重复读取当前文件得到的相同内容;
- `citeable=false` 的失败、拒绝或缺失工具记录只能在候选确实依赖该次查询时引用，用于向 Verifier 声明证据缺口；它不能证明或反驳问题;
- `found + partial` 中已返回的解析关系可以支持“该关系存在”，但不能支持范围完整、其他路径不存在或保护缺失；failed、indeterminate 和不可引用记录只能表达事实缺口;
- location 只说明如何找到位置,不能单独证明问题成立;
- 没有使用外部事实时返回空 evidence_refs，系统会自动使用当前 task patch；
- 不得猜测、构造或修改编号;
- 不得把 summary、Plan objectives 或 knowledge bundle 当仓库证据。

证据引用描述的是候选实际使用的事实，而不是为候选挑选有利材料。最多 3 条时优先保留决定候选能否成立的 mechanism、reachability 和 counter；无法在 3 条内表达必要支持与直接反证时，应在输出前缩小主张，仍无法自洽则不形成候选。

候选必须先通过“主张—证据”检查再输出：

- patch 直接可见的局部机制可以只依赖自动绑定的 patch；
- caller、callee、listener、callback、外部契约、生产可达性或运行时影响等非局部主张，必须有对应的 Cxx/Txx 外部事实引用；
- 调用图只能证明返回的静态关系存在；如果候选还主张具体条件、执行顺序、参数值传播、状态变化或保护逻辑缺失，必须引用能够直接显示该语义的源码或其他事实；
- 如果非局部事实尚未查到，不得仅降低 confidence 后继续输出原主张；应先调用相应图谱工具，
  或删去未经证明的部分，保留仍由现有事实独立成立的局部问题；
- 工具不可用不等于事实成立，也不等于事实不存在。无法证明的部分必须明确删掉或不形成候选。
