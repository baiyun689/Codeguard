## 共享图谱工具合同

三个审查员共享以下事实工具。工具只返回仓库中的静态事实，不判断是否存在问题、是否可利用、实际影响或严重程度。

调用工具只能使用 `<symbol_context>` 或先前图谱结果中真实出现的稳定 `symbol_id`。不得根据文件名、类名、方法名或惯用命名猜测 symbol。

### 工具能力

- `inspect_structure(symbol_id)`：查询当前 symbol 的一跳双向关系，包括声明、调用、实现/继承/覆写及字段读写。它适合了解局部结构，但不能证明多层调用路径、执行顺序或影响范围。
- `inspect_change_impact(symbol_id)`：METHOD/CONSTRUCTOR 沿已解析调用关系向上查询最多三层的 caller 和框架入口；FIELD 返回一跳读写者；TYPE 返回一跳继承/实现者。它只能证明返回关系存在，不能证明未返回的影响一定不存在。
- `inspect_path(symbol_id, path_kind="behavior", max_depth=3)`：沿已解析调用关系向下查询最多三层的 callee，并附带相关字段读写、继承实现和框架入口事实。它用于定位可能相关的执行路径，不能单独证明分支顺序、状态值传播、并发交错或某条路径运行时一定执行。
- `inspect_path(symbol_id, path_kind="security", max_depth=3)`：在最多三层下游调用遍历中返回敏感调用命中，并附带起始 symbol 的框架入口线索。结果不保证包含起点到敏感调用的完整连通路径，也不能单独证明参数级数据传播、输入可控性、净化有效性、保护逻辑缺失或漏洞可利用性。
- `get_file_content(symbol_id)`：读取已解析 symbol 的有界源码片段。METHOD/CONSTRUCTOR 返回注解、签名和方法体，TYPE 返回类型定义，FIELD 返回字段声明，FRAMEWORK_ENTRYPOINT 返回对应注解。它用于核对条件、语句顺序、状态赋值、异常处理和具体参数使用，不能代替跨文件关系查询。

### 查询策略

工具既可验证已有假设，也可在领域 Prompt 规定的触发条件下执行一次有界关系侦察。首次侦察用于判断变更是否连接到值得继续检查的外部关系，不要求事先确认问题。

1. caller、入口、影响范围使用 `inspect_change_impact`。
2. callee、callback/listener 关联和下游调用使用 `inspect_path(path_kind="behavior")`。
3. 安全相关的下游调用和敏感操作线索使用 `inspect_path(path_kind="security")`。
4. 一跳结构、继承实现和字段读写使用 `inspect_structure`。
5. 条件分支、语句顺序、状态赋值、参数使用或异常处理使用 `get_file_content`；应先通过 symbol context 或图谱事实定位需要读取的 symbol。

一次优先查询与当前变更最相关的一个 symbol。首次结果没有暴露相关外部关系时停止探索；存在与主张直接相关的新事实缺口时，才执行一次补充查询。不得重复查询同一事实，也不得为了增加证据数量调用工具。

### 解释限制

- 图谱关系证明“静态解析到该关系存在”，不自动证明具体值流、分支顺序、运行时必然性或影响严重程度。
- `partial` 表示只可使用已经返回的正向事实，不能据此断言其他关系不存在。
- `indeterminate`、失败、空响应或未解析关系只表示事实缺口，既不是支持证据，也不是反证。
- `not_found + complete` 只适用于声明的 source scope 和查询范围，不能扩大到反射、动态代理、运行时配置或范围外路径。
- 新增文件的完整 patch 已经包含全部新增代码时，不要重复读取同一 symbol；只有需要 patch 外符号或其他实现细节时才调用源码工具。
